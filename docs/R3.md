# R3 — Terminal suite modules

R3 covers **R3a, R3b, R3c, R3d, and R3e**. The earlier informal “phase 3 = R2” mapping did not reflect the requested scope. The R2 tracker covers only part of this phase. The final report and dossiers are in [PHASES-1-3.md](PHASES-1-3.md).

## Implemented components

| Module | Features | Initial scope |
|---|---|---|
| R3a | Assembly, registers, stack, breakpoints | Eight instructions from the PC, general-purpose registers and EFLAGS, eight stack words, and declared breakpoint location and state |
| R3b | Maps, permissions, dumps, search, pointers | Explicit bounded ranges with reporting for unreadable memory, cycles, null pointers, and limits |
| R3c | Chunk headers, main_arena, fastbins, bins, tcache | glibc 2.36 with matching debug types, one arena and one thread, and bounded forward traversal |
| R3d | Offline patterns, offsets, and ELF properties | Patterns up to 1 MiB and static properties of little-endian AMD64 ELF64 files. No exploitability verdict. |
| R3e | Input, snapshots, notes, comparison, export, reopening | Self-contained local dossiers with consistent build and run IDs. Process restoration is outside the scope. |

These are initial implementations in the stated scope. They do not establish feature parity with GEF or Pwndbg. The validated runtime was Debian 12 x86-64 with GDB 13.1, Python 3.11.2, and glibc 2.36 under QEMU TCG on an ARM64 Mac. Kali, native hardware, a GUI, other allocators and architectures, multiple threads, and remote sessions remained unvalidated at this stage. The installable alpha is R4.

## Getting started in the Linux lab

Use a new directory for each test in the project checkout:

```sh
mkdir work/demo-r3-001
cc -g3 -O0 -fno-omit-frame-pointer -Wall -Wextra -Werror examples/heap_lab.c -o work/demo-r3-001/heap_lab
python3 scripts/ressembly-experiment.py create work/demo-r3-001/experiment.json work/demo-r3-001/heap_lab "First R3 experiment"
gdb -nx work/demo-r3-001/heap_lab
```

In GDB, load the suite and inspect the project-owned fixture at a debug checkpoint:

```gdb
source src/ressembly_suite.py
rs-help
break lab_ready
run
rs-context
rs-maps
rs-experiment-snapshot work/demo-r3-001/experiment.json ready
```

The fixture uses debug checkpoints, with no allocator markers. R2 collects selected malloc and free operations. R3 rereads stopped state. The fixture demonstrates that a reused address can receive a new object identity. The limits in [R2.md](R2.md) apply to allocation events and observed value differences.

Reopen, annotate, or export a dossier outside GDB:

```sh
python3 scripts/ressembly-experiment.py show work/demo-r3-001/experiment.json
python3 scripts/ressembly-experiment.py note work/demo-r3-001/experiment.json "Selected snapshot. Intervening writes are unknown."
python3 scripts/ressembly-experiment.py export work/demo-r3-001/experiment.json work/demo-r3-001/export.json
```

The R2 history remains a separate file. The `import-snapshot` command can add it to the dossier using its `metadata.target_sha256` and `metadata.run_id`. The importer checks those fields against the content and the dossier's build. The report marks the import as supplied data. R2 capture identity and R3 process identity use distinct schemes. Comparing them reports `same_run: null`.

## Loading and compatibility

The suite loader loads separate modules. It skips registration if a current module is already loaded. Loading the suite again preserves the active R2 session. The loader requires no changes to `.gdbinit`, global installation, service, or AI dependency. GEF and Pwndbg remain external comparison tools. Coexistence has not been certified.

Use the historical R1 marker adapter **in a separate GDB session**. The suite loader rejects a session where that adapter is already loaded. Load the marker adapter only in its own session. Dossiers from R1 can be imported offline with consistent metadata.

## Repeatable validation

Use a new directory for each command in the Linux lab:

```sh
python3 scripts/validate-debug-linux.py work/r3-debug-NEW
python3 scripts/validate-heap-view-linux.py work/r3-heap-NEW
python3 scripts/validate-experiments-linux.py work/r3-experiments-NEW
python3 scripts/validate-suite-linux.py work/r3-suite-NEW
```

The separate offline lab utility validator is listed in the [lab tools guide](R3-LABTOOLS.md). The suite validator exercises the modules with the R2 collector active. It loads the suite first in one path and loads individual modules first in another. It checks reloading, unchanged registers and events during inspection, distinct identities after address reuse, completion of frees, and dossier export. The report lists assertions and sessions separately, since one process can contain many assertions.
