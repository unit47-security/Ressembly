# R6 — glibc 2.43 allocator profile

November 13, 2026. The profile was implemented and tested with a real Linux x86-64 kernel under QEMU TCG on an ARM64 Mac. Final packaging and cleanup checks are recorded separately in `work/r6-gates/acceptance.json`. R6 validation was carried out locally.

## Scope

Malloc and free collection, calloc and realloc history, and structural heap inspection cover glibc **2.43** while retaining **2.36**. The new matrix used Kali 2026.3 with matching glibc, debug symbols, and headers **2.43-4**, GDB 17.2, Python 3.14.7, and GCC 16.2.0. Nearby version strings such as 2.43.1 and 2.430 are rejected. A release number alone does not qualify other builds of the same version. Types, ABI, and symbols must also match.

R6 covers launched local processes on Linux SysV AMD64 with one thread and one arena. Attach, fork, multiple threads, other allocators, and native performance are outside the R6 scope. The collector distinguishes allocator operations from watched value changes. Four selected hardware regions provide partial coverage of memory accesses. An isolated signal does not establish exploitability.

## Implemented differences

- The 2.43 profile reports that fastbins are absent. It distinguishes absence from an empty list. The 2.36 profile retains ten fastbins.
- The tcache has 76 size classes compared with 64 in 2.36. The `num_slots` fields count available slots. Active occupancy is derived from the configured capacity in `mp_`.
- Inactive and disabled dummy pointers are recognized explicitly. Their zeroed counters do not produce inferred free objects.
- The `tcache_max` threshold is distinct from the traversal limit per list. The corpus tests large-entry reuse behavior and rejection of mismatched sizes for the examined build.
- Arena and tcache layout, fields, widths, offsets, and type provenance are checked. Incompatible versions and layouts are rejected.
- Version detection prefers a bounded read of a symbol verified to belong to the loaded libc. If symbols are absent, the collector can use the libc banner. The structural view still requires matching debug symbols.
- On 2.43 the R2 collector records external operations. It suppresses its own entry hooks during a transaction to avoid counting internal recursion during the first free. The metadata records the exclusion of nested and reentrant calls, as in R5.
- The 2.43 collector handles returns across tail calls that can invalidate a FinishBreakpoint during a pause. Its return breakpoints are removed on completion. The 2.36 profile retains FinishBreakpoint. A missing return remains incomplete or unknown.

Address reuse and realloc retain the identities defined in [R5-HISTORY.md](R5-HISTORY.md). The policy for realloc with a nonnull pointer and zero size reflects the tested glibc behavior and is platform specific.

## Validation and reproduction

97 Python and 14 JavaScript tests passed. Results are in `work/r6-gates/final-python.txt` and `final-javascript.txt`. Counts for aggregate groups and nested tests describe the same validation runs.

The `scripts/validate-r6-linux.py` corpus compares Ressembly snapshots with a separate GDB session without Ressembly, using direct field and memory reads. The final Kali 2.43 path includes **24 groups**. They cover the nested R2 and R5 suites with 22 and 14 cases, two pause and resume checks inside helpers, error and version handling, type checks, disabled-cache behavior, default and configured capacity, traversal limits, cycles, and unreadable memory. Author and independent replay dossiers were retained on the Mac. The external acceptance record lists final outcomes and paths.

Developer validation from the source checkout:

```sh
python3 -m unittest discover -s tests
python3 scripts/validate-r6-linux.py work/r6-NEW
```

These validators and developer tests are excluded from the user package.

The 2.36 regression used a Debian sysroot with matching loader, libc, headers, startup files, and symbols under the same Kali kernel. It left the guest system untouched. All 16 groups passed, including the complete R2 and R5 suites. This result covers a **2.36 target in a mixed environment**. It does not qualify an entire new Debian installation. The validator also verifies the target version for nested collectors. `getconf` alone reports the host libc.

An isolated mutation treats the available-slot count as occupancy. The expected result is a failure with `occupancy mismatch`. Production code was untouched. Earlier attempts were retained. They found the missing fastbins and tail-call issue, then led to corrections to harness assumptions about GDB 17 diagnostics and small- and large-entry reuse. Those attempts are excluded from the pass counts.

## Storage and cleanup

The lab used one temporary sparse disk, with no base copy or overlay, and a minimal local QEMU runtime. The agreed limit was **3,000,000,000 bytes**. The measured provisioning peak was **2,837,028,864 bytes**. Guest cleanup and fstrim reduced the lab to approximately 2.25 GB. Measurements are in `work/r6-lab/budget.jsonl`.

After final testing, the workflow keeps logs, results, manifests, scripts, and source code and removes the VM, runtime, and dedicated keys. The actual cleanup outcome is in `work/r6-gates/cleanup.json`. The old launch scripts are historical references and require rebuilding the lab before use. Pre-existing shared tools under `/opt/homebrew/opt` are separate.
