# R2 — selective object history and one observed region

November 13, 2026. R2a and R2b cover selected allocation lifetimes and one selected observation region in the environment below. Daybreak, GEF, Pwndbg, external services, and AI are optional for this milestone.

## Compatibility and tests

The lab ran **Debian 12 Linux x86-64**, glibc **2.36**, GDB **13.1**, GDB Python **3.11.2**, and GCC **12.2** under full QEMU TCG emulation on an ARM64 Mac. The dossiers preserve the loaded libc path, SHA-256 and banner, the target and build, PID, inferior, run UUID, and context. The host's libc version alone does not establish which libc the target loaded. Native performance, physical hardware, and Kali support were outside this test.

R2a preceded R2b. The intermediate `work/r2a-002` run observed allocations and frees without program markers, address reuse with distinct generations, a null free, a failed allocation, and exit status zero. The retained `r2a-001` run exposed signed register interpretation in GDB. The collector now normalizes allocator argument and return values as unsigned 64-bit integers for this profile. The first R2b run then observed two expected changes to one byte and closed the region before free.

The final runs below are separate from the retained failed and intermediate attempts.

## Collected evidence

- The ledger records selected entries and returns for glibc malloc and free under the SysV AMD64 ABI.
- An object's identity is `address:generation` within a run UUID. Reusing an address creates a new identity. Addresses from separate runs are not interchangeable identities.
- `free_begin` puts an object in `free_pending` until an observed return. A missing return leaves the outcome unknown.
- A single explicitly selected region can cover 1, 2, 4, or 8 aligned bytes within the requested size of a live object. The initial read is a baseline sample.
- A hardware watchpoint reports observed value changes. Writes that leave the value unchanged may be absent, and the report does not reconstruct a complete write history.

Events retain order, thread, stop PC, and provenance when available. Missing context is explicit. A watchpoint PC records the stop location after the relevant instruction. It is not automatically identified as the writer's address.

## Collector workflow

The heap loader delegates to `ressembly.heap_gdb` so collector state does not remain in the loader's script globals. The workflow uses a fresh GDB session and the project-owned `examples/heap_lab.c` fixture. This fixture uses debugger checkpoints and does not emit allocator markers. The heap and marker collectors are mutually exclusive.

A session reserves a new JSON destination and accepts an event limit from 1 through 10,000, with 1,000 as the default. It can show or save the current ledger and can end explicitly as interrupted. Starting a new run requires a new GDB session. Saves use local atomic replacement. A forced stop can lose observations made after the last save.

Automatic continuation applies to stops owned by the collector. User breakpoints and signals return control to the user, including a user breakpoint at a collector hook. Return tracking and watchpoint cleanup happen through stop handling or explicit commands. The collector refuses to resume through an allocator frame that vanished without an observed return. Manual changes to the stack or PC are outside this workflow.

## Coverage and errors

A region starts as `pending`. Coverage becomes active only after watchpoint insertion and a subsequent stop after resume. Failed insertion leaves the region inactive. The collector refuses software fallback. Other debugger breakpoints and watchpoints can consume the available hardware slots.

Coverage ends at free entry before allocator bookkeeping changes. A later object at the same address requires a new selection. An ended window, a rejected selection, an inactive window, and a successful baseline sample remain distinct.

The supported configuration is a local process launched by GDB, stopped in the lab, with one inferior and one thread. Attach, fork, other architectures and allocators, and nested calls are outside this milestone. Known calloc and realloc entries are explicitly rejected by this version to avoid silently changing tracked objects. Unobserved operations remain outside coverage. An unattributed free gives no basis for a use-after-free or double-free verdict.

Read failures, event limits, missing returns, target or run changes, and exhausted hardware resources are reported explicitly. Rejected selections do not extend coverage. The last observed state is a point-in-time result. A live object at the last stop does not establish a leak.

## Automated validation

The Linux harness builds the owned C fixture with symbols and without optimization, invokes real GDB, and retains command logs, exit codes, JSON, and identities. Each anticipated negative case checks for the specific expected diagnostic and return status. Unrelated tracebacks are failures.

The matrix covers repeated ledger and region runs, user breakpoints, incomplete returns, signals, invalid regions and identities, watchpoint conflicts and exhaustion, unavailable memory, unsupported allocator operations and repeat runs, event budgets, an independent allocator reference, and timing controls. The unreadable-memory case operates on a page in the lab fixture and is not a finding about third-party software.

The reported cost is total subprocess time, including GDB startup and dossier creation in the emulated guest. It does not measure instruction-level overhead or native performance.
